# Release 8.2.0 – Inventario QR, Transferencias concurrentes y Bajas SABS

## Resumen de la Versión

Esta versión incorpora los siguientes módulos y funcionalidades del sistema **Activa360**:

1. **Inventario QR (Guillermo Daza)**: nuevos endpoints de escaneo y registro de inventario, modelo `InventoryRecord` con restricción de concurrencia `@@unique([campaignId, assetId])`.
2. **Transferencias Concurrentes (Guillermo Daza)**: refactor de `TransferAssetService` usando transacciones con bloqueo pesimista `SELECT FOR UPDATE` para prevenir race conditions. FK `Transfer.assetId → Asset.id`.
3. **Módulo Compliance: Bajas SABS (Rita Nina)**:
   - **Feature 1 — Filtros en listado de Bajas (`GET /bajas`)**: filtrado individual y combinado por `estado` (`INICIADA`, `APROBADA`, `RECHAZADA`), término del activo (búsqueda insensible a mayúsculas por ID, código QR o nombre) y rango temporal (`fechaDesde` y `fechaHasta`).
   - **Feature 2 — Paginación en `GET /bajas`**: soporte para `page` (mín. 1, default 1) y `limit` (mín. 1, máx. 100, default 10), con respuesta estandarizada `{ data: Baja[], meta: { total, page, limit, totalPages } }`.
   - **Feature 3 — Comentario al rechazar (`POST /bajas/:id/rechazar`)**: validación del campo obligatorio `motivoRechazo` (mínimo 5 caracteres), verificación de estado `INICIADA`, cambio a `RECHAZADA` persistiendo el motivo en base de datos (`Baja.motivoRechazo`), restauración del activo a revisión técnica (`Dañado` u `Obsoleto`) y retorno de la entidad actualizada.
   - **Integración Frontend**: página de Bajas (`frontend/src/pages/Bajas.tsx`) con barra de filtros, controles de paginación interactiva, modal de confirmación de rechazo con validación de motivo y visualización del motivo en tarjetas con estado `RECHAZADA`.

## Contrato OpenAPI (`openapi.json`)

Los nuevos endpoints y DTOs están completamente documentados con decoradores de `@nestjs/swagger`:
- `GET /bajas`: parámetros de consulta `estado`, `activo`, `fechaDesde`, `fechaHasta`, `page`, `limit`; respuesta tipada `PaginatedBajasResponseDto`.
- `POST /bajas/{id}/rechazar`: parámetro de ruta `id`, cuerpo de solicitud tipado `RejectBajaDto` (`motivoRechazo`), respuestas `200` (éxito), `400` (motivo inválido o estado != INICIADA), `404` (no encontrado).
- Flujo de CI automatizado: `.github/workflows/openapi-ci.yml` ejecutando exportación, control de drift (`git diff --exit-code openapi.json`) y linter Spectral con `.spectral.yaml`.

## Instalación y Ejecución
```bash
npm install
npx prisma db push       # sincroniza esquema con campo motivoRechazo
npm run build            # compila backend NestJS
npm run openapi:export   # exporta contrato OpenAPI
npm test                 # ejecuta suite de pruebas Jest
npm run start:dev        # arranca API en localhost:3000

# Frontend
cd frontend && npm install && npm run build && npm run dev
```

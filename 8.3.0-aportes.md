# Release 8.3.0 – Sincronización Offline, Bajas SABS y Asignación de Custodios

## Resumen

Esta versión consolida la **Demo 3** de Activa360, integrando tres funcionalidades fundamentales de la especificación funcional (FSD) para la gestión integral de activos fijos institucionales, acompañada de la infraestructura de producción en contenedores, auditoría de seguridad y análisis técnico de rendimiento y arquitectura:

- **Sincronización Offline (FSD-UC-002, Guillermo Omar Daza Alcalá)**: Procesamiento en lote mediante `POST /activos/sync` con algoritmo de resolución de conflictos por timestamp (LWW - Last Write Wins), actualización atómica de ubicación y estado en `Asset`, y registro histórico de coordenadas en `Movement`.
- **Workflow de Bajas SABS (FSD-UC-003, Josefina Rojas)**: Gestión normativa de bajas de bienes patrimoniales bajo normativa boliviana (D.S. 0181 - SABS). Endpoints `POST /bajas`, `GET /bajas`, `POST /bajas/{id}/aprobar` y `POST /bajas/{id}/rechazar`. Validación de rol institucional, registro de justificación y evidencia documental, y restauración condicional de estado técnico en caso de rechazo.
- **Asignación a Custodio (FSD-UC-004, Rita Nina)**: Trazabilidad de custodia patrimonial con `POST /activos/asignar`, `GET /activos/asignaciones` y `GET /activos/empleados`. Registro de custodio responsable, destino, fecha y observaciones en `AssignmentRecord`, asegurando la responsabilidad sobre el bien.
- **Infraestructura de Producción**: Dockerfiles multi-stage para Backend (`Dockerfile`) y Frontend (`frontend/Dockerfile`) optimizados para `node:20-alpine` y `nginx:alpine` con usuarios no privilegiados, validados con Hadolint (0 advertencias/errores) y Trivy. Orquestación declarativa mediante `compose.yaml` con healthchecks coordinados (`condition: service_healthy`).
- **Análisis de Rendimiento (k6 en `bench/load-test.js`)**: Prueba de carga a ritmo fijo (20 req/s, 30s) en 3 corridas consecutivas con 100% de éxito, mediana de latencia p(95) de 7.55 ms y 0.00% de fallos.
- **Análisis Arquitectónico (E3)**: Evaluación técnica de extracción modular del servicio de Bajas SABS (`compliance-sabs-service`), contrastando interfaz monolitica vs. distribuida (RPC/eventos asíncronos).
- **Contrato OpenAPI**: Todos los nuevos endpoints documentados y validados en `openapi.json` con tags, esquemas de DTOs y respuestas HTTP correspondientes.

## Instalación y Verificación

### Opción 1: Despliegue con Docker Compose (Recomendado para Producción)
```bash
docker compose -f compose.yaml up -d --build --wait
```
- Frontend: `http://localhost:80`
- Backend API: `http://localhost:3000`
- OpenAPI Docs: `http://localhost:3000/api-docs`

### Opción 2: Desarrollo Local
```bash
npm install
npx prisma migrate deploy   # aplica migraciones pendientes
npm run build              # compila la solución
npm run start:dev          # arranca la API en modo desarrollo
```

### Ejecución de Pruebas de Carga (k6)
```bash
Get-Content bench/load-test.js | docker run --rm -i --network activa360-release-820_default -e TARGET_URL=http://backend:3000 grafana/k6:latest run -
```
